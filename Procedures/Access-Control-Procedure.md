# Access Control Procedure
## ISO/IEC 27001:2022 Information Security Management System

### 1. Purpose
This procedure defines how access to systems, applications, data, and physical facilities 
is requested, approved, provisioned, reviewed, and revoked. It ensures compliance with 
ISO/IEC 27001:2022 Annex A access control requirements.

---

### 2. Scope
This procedure applies to:
- All employees, contractors, and third‑party personnel
- All systems, applications, cloud services, and physical areas
- All access types (user accounts, admin accounts, privileged access, API keys)

---

### 3. Roles & Responsibilities

#### **ISMS Manager**
- Oversees access control governance
- Ensures compliance with policies and procedures

#### **System Owners**
- Approve access requests
- Validate user access levels

#### **IT Administrators**
- Provision, modify, and revoke access
- Maintain access logs and records

#### **HR Department**
- Notifies IT of onboarding, role changes, and terminations

#### **Users**
- Use access responsibly
- Report suspicious activity immediately

---

### 4. Access Request Process

#### **4.1 Initiation**
Users must submit an access request including:
- Name and role
- System/application required
- Type of access (standard, privileged)
- Business justification

Requests must be submitted through the approved ticketing system.

#### **4.2 Approval**
- System Owner must approve all access requests.
- Privileged access requires ISMS Manager approval.
- No access may be provisioned without documented approval.

#### **4.3 Provisioning**
IT Administrators must:
- Create accounts following least privilege
- Apply MFA where required
- Assign roles based on approved access
- Record provisioning actions in the access log

---

### 5. Privileged Access Management (PAM)

- Privileged accounts must be strictly limited.
- Admin credentials must not be shared.
- Privileged sessions must be logged and monitored.
- Privileged access must be reviewed monthly.

---

### 6. Access Modification

Changes to access (role change, additional permissions) must:
- Follow the same request and approval process
- Be documented in the access log
- Be validated by the System Owner

---

### 7. Access Review

#### **7.1 Frequency**
Access reviews must occur:
- Quarterly for standard users
- Monthly for privileged users

#### **7.2 Review Requirements**
System Owners must verify:
- Access is still required
- Access level is appropriate
- No unauthorised accounts exist

Findings must be documented and remediated.

---

### 8. Termination & Revocation

#### **8.1 Trigger**
Access revocation must occur when:
- Employment ends
- Contract ends
- Role changes
- Access is no longer required

HR must notify IT immediately.

#### **8.2 Revocation Steps**
IT Administrators must:
- Disable accounts within 24 hours
- Remove access rights
- Collect badges, keys, and devices
- Document revocation in the access log

---

### 9. Physical Access

- Physical access must follow the same request/approval process.
- Access badges must be issued only after approval.
- Visitor access must be logged and escorted.
- Badge access must be reviewed quarterly.

---

### 10. Monitoring & Logging

- All authentication events must be logged.
- Privileged actions must be monitored.
- Failed login attempts must generate alerts.
- Logs must be retained for audit purposes.

---

### 11. Non‑Compliance

Non‑compliance may result in:
- Revocation of access
- Disciplinary action
- Contract termination (for third parties)

---

### 12. Review
This procedure will be reviewed annually or after major system or organisational changes.

---

### 13. Approval
Approved by senior management as part of the ISMS governance framework.
