# Annex A.8 – Technological Controls  
ISO/IEC 27001:2022 Annex A.8 contains 34 controls focused on technical security measures, system protection, secure development, and operational technology.

---

## A.8.1 User Endpoint Devices  
Endpoints must be hardened, encrypted, patched, and monitored using EDR.

## A.8.2 Privileged Access  
Privileged accounts must use MFA, logging, monitoring, and strict RBAC.

## A.8.3 Information Access Restriction  
Access must be restricted using ACLs, RBAC, and least‑privilege principles.

## A.8.4 Source Code Security  
Secure SDLC, code reviews, static analysis, and no hardcoded secrets.

## A.8.5 Secure Authentication  
Strong passwords, MFA, secure token handling, and session management.

## A.8.6 Capacity Management  
Systems must be monitored for CPU, RAM, storage, and network capacity.

## A.8.7 Protection Against Malware  
EDR, antivirus, sandboxing, and SOC monitoring must be enabled.

## A.8.8 Logging  
Centralised logging of authentication, access, system events, and errors.

## A.8.9 Monitoring Activities  
SOC monitors logs, alerts, anomalies, and suspicious behaviour.

## A.8.10 Clock Synchronisation  
All systems must use NTP for consistent timestamps.

## A.8.11 Network Controls  
Firewalls, segmentation, VPN, secure routing, and IDS/IPS.

## A.8.12 Web Filtering  
Block malicious domains, phishing sites, and high‑risk categories.

## A.8.13 Secure Configuration  
Baseline hardening for servers, endpoints, cloud, and network devices.

## A.8.14 Change Management  
All changes must follow the Change Management Procedure.

## A.8.15 Vulnerability Management  
Regular scanning, patching, remediation, and reporting.

## A.8.16 Technical Review  
Periodic review of configurations, firewall rules, and access controls.

## A.8.17 Information Deletion  
Secure wiping, cryptographic erasure, and validated deletion processes.

## A.8.18 Data Masking  
Mask sensitive fields in logs, applications, and test environments.

## A.8.19 Data Leakage Prevention  
DLP tools must monitor and block unauthorised data transfers.

## A.8.20 Information Backup  
Daily incremental, weekly full, and monthly offsite backups.

## A.8.21 Redundancy  
Failover systems, multi‑AZ cloud redundancy, and resilient architecture.

## A.8.22 Cryptographic Controls  
AES‑256, TLS 1.2+, secure key storage, and approved algorithms only.

## A.8.23 Key Management  
Keys stored in secure vaults, rotated annually, and access restricted.

## A.8.24 Secure Development  
OWASP, secure coding standards, threat modelling, and code scanning.

## A.8.25 Testing  
Functional, security, and regression testing before deployment.

## A.8.26 Secure Coding  
No hardcoded credentials, input validation, sanitisation, and safe APIs.

## A.8.27 Outsourced Development  
Suppliers must follow NovaPay’s secure development requirements.

## A.8.28 Change Detection  
File integrity monitoring (FIM) for critical systems.

## A.8.29 Technical Vulnerability Disclosure  
Responsible disclosure process for reporting vulnerabilities.

## A.8.30 Configuration Management  
Version control, configuration baselines, and change tracking.

## A.8.31 Data Integrity  
Checksums, hashing, validation, and tamper detection.

## A.8.32 Data Availability  
Redundant systems, backups, and high‑availability architecture.

## A.8.33 Secure Disposal  
Cryptographic erasure and certified destruction of media.

## A.8.34 Monitoring of Technical Controls  
Continuous monitoring of all technical controls by SOC.

---

## Summary  
A.8 ensures NovaPay’s technology stack is secure, monitored, resilient, and aligned with modern cybersecurity best practices.
